# Задание 4. Узкие места при миграции

[Диаграмма Исикавы в draw.io](ishikawa.drawio)

## Текущая ситуация и цель

Сейчас Excel, сканы, файловые базы 1С, почта и доменные службы работают на одном сервере. Данные вводятся вручную, платежи дублируются в Excel и 1С. ККМ подключены по TCP/IP через компоненту 1С на OLE; две программы 1С интегрированы между собой.

Миграция затронет хранение, запись на приём, медкарты, оплату и лабораторию. [Целевая система](../Task2/README.md) должна поддержать филиалы и пятикратный рост данных.

На диаграмме показаны возможные причины сбоев: точные объёмы данных и характеристики оборудования в задании не указаны.

## Проверка перед переходом

1. Замерить время поиска пациента, открытия карты, записи и оплаты, долю ошибок, загрузку CPU, памяти и диска, блокировки БД и очереди. Метрики собирать в VictoriaMetrics.
2. Загрузить тестовые данные в пятикратном объёме. Число одновременных пользователей увеличивать по плану филиалов. Во время проверки запускать также импорт, аудит и резервное копирование.
3. Предварительные критерии: поиск и запись до 2 секунд для 95% запросов, технические ошибки менее 1%. Согласовать значения с клиникой. Потери документов, двойные записи и повторные списания недопустимы; очередь после пика должна сокращаться.
4. Проверить обрыв связи, недоступность лаборатории, потерю ответа об оплате и отказ проверки прав. Повторы не должны создавать дубли, а сбой проверки прав — открывать доступ.

## Порядок переключения

Сначала перенести пациентов и запись, затем медкарты, анализы и платежи. Перед переключением каждого процесса проверить резервную копию, остановить изменения, загрузить последние данные и выполнить сверку. Старую часть оставить для чтения.

Если проверки не пройдены, остановить переход. Для отката приостановить операции и перенести подтверждённые изменения, сделанные после переключения, в прежнюю систему. После сверки вернуть ей право записи. Простое восстановление старого снимка потеряет новые записи и платежи.
