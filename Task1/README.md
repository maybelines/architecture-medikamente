Анализ выполнен по описанию компании. Названия хранилищ на схемах условные; меры, не указанные в задании, требуют проверки.

## Какие данные нужно защищать

| Данные | Где находятся сейчас | Теги | Способы защиты |
| --- | --- | --- | --- |
| Ф. И. О., дата рождения, контакты, адрес, место работы или учёбы | Реестр пациентов в Excel, анкеты, сканы | PII, MEDICAL | Шифрование дисков и каналов; маскирование телефона и email в списках; удаление лишних полей из выгрузок |
| Договоры | Файлы и сканы | PII, MEDICAL | Шифрование; доступ ресепшена и уполномоченного бухгалтера; маскирование реквизитов в рабочих копиях |
| Записи к врачам | Журналы в Excel | PII, MEDICAL | Шифрование, доступ ресепшена и соответствующего врача; patient_id вместо копирования контактов |
| Заболевания, диагнозы, заключения, анализы | Анкеты, Excel, JPG, PDF | PII, MEDICAL | Шифрование, доступ лечащего врача; обезличивание перед аналитикой |
| Платежи, чеки, связь пациента с услугой | Excel, ККМ, 1С:Бухгалтерия | PII, MEDICAL, FINANCE | Шифрование, кассовая и бухгалтерская роли; отчёты по группам без пациентов |
| Данные сотрудников, зарплаты, налоги | 1С:Бухгалтерия | PII, HR, FINANCE | Шифрование, отдельная кадровая роль; обезличенные сводные отчёты |
| ТМЦ, закупки, контакты поставщиков | 1С:Торговля и склад, 1С:Бухгалтерия | INTERNAL; PII для данных физлиц | Шифрование, доступ склада и бухгалтерии; исключение контактов из общих отчётов |

Факт обращения за медицинской помощью относится к врачебной тайне, поэтому журнал записи и связанный с пациентом платёж тоже требуют защиты: [ст. 13 № 323-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_121895/9f906d460f9454a8a0d290738d9fc2798c1e865a/).

Помимо основных файлов, нужно проверить вложения Exchange, локальные и резервные копии, выгрузки и названия папок. Если в названиях есть Ф. И. О. или дата рождения, заменить их на patient_id. Эти места могут содержать неучтённые персональные данные.

Маскирование (обфускация) скрывает часть значения: `+7 *** ***-12-34`. Замена имени на ID сохраняет связь с человеком через справочник и требует защиты. Для обезличенных отчётов используются агрегаты, обобщение возраста и дат, объединение малых групп.

## Тегирование

На Windows Server использовать [FSRM](https://learn.microsoft.com/en-us/windows-server/storage/fsrm/fsrm-overview) с File Classification Infrastructure. Для него нужен том NTFS.

1. Создать свойства «да/нет»: `PII`, `MEDICAL`, `FINANCE`, `HR`, `INTERNAL`. Один файл может иметь несколько тегов.
2. Назначать теги по папкам: медкарты и анализы — `PII + MEDICAL`, платежи — `PII + MEDICAL + FINANCE`, кадры — `PII + HR + FINANCE`. Дополнительно проверять содержимое текстовых документов. Сканы размечать по папке.
3. Запускать классификацию для новых файлов и по расписанию. До проверки сомнительные документы держать в закрытой входящей папке.
4. Для смешанного Excel применять ограничения всех его категорий. База 1С получает все содержащиеся в ней категории, а права на документы задаются в 1С.
5. Выгрузки и копии повторно классифицировать в месте назначения: метки могут потеряться. Снимать тег только после проверки ответственным сотрудником.

Теги обозначают категории. Доступ ограничивается группами AD, правами NTFS и ролями приложений. Например, ресепшен видит записи и договоры, врач — карты своих пациентов; общий тег MEDICAL не даёт одинакового доступа к ним. После перевода 1С в клиент-серверный режим FSRM применяется к выгрузкам и копиям, а категории документов учитываются внутри 1С.

## Меры по этапам потока

| Этап | Что использовать |
| --- | --- |
| Сбор | Раздельные административная и медицинская анкеты; только необходимые поля; учёт цели, основания обработки и согласия, когда оно требуется |
| Доступ | Именные учётные записи, AD, NTFS, роли 1С; отзыв доступа при увольнении. Клиент-серверная 1С с запретом прямого доступа пользователей к базе |
| Хранение и передача | BitLocker, SMB 3 с шифрованием, HTTPS для API, VPN между филиалами. ККМ — отдельный сегмент и разрешённые узлы. Подробности в [задании 3](../Task3/README.md) |
| Аудит | Чтение, изменение и удаление файлов в Windows, журнал регистрации 1С. События отправляются на отдельный узел; массовое чтение и отказы вызывают оповещение |
| Копии и удаление | Зашифрованные копии отдельно от сервера, проверка восстановления. Сроки по видам документов, удаление лишних копий и учёт удалений при восстановлении |

Для Data Lineage вести реестр: источник, получатель, набор данных, цель, дата и ответственный. Например: `медкарта → заказ лаборатории → результат → медкарта`. ID выгрузки и ссылка на источник позволяют найти копии при исправлении или удалении.

По запросу пациента прекращается обработка, утратившая законное основание. Документы с обязательным сроком хранения остаются с ограниченным доступом: [ст. 5, 6 и 21 № 152-ФЗ](https://mintrud.gov.ru/docs/laws/130).
